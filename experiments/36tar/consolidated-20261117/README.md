# 剪枝、历史读取与跨模型迁移：阶段收束

本目录是36tar截至2026-11-17的交付快照，承接已合并PR #10。包含已完成的工程收益、7B迁移和组合比较，以及单列的失败教训。没有修改默认模型或搭档文件。持续进度仍以本地《实验总纲.md》为准，本文件不是实时作业状态表。

## 1. 已形成的可复用成果

- **因果输入与有界预取**：视频按真实时间顺序处理，问题只使用当时可见帧，问答分支结束后释放。预取和剪枝可以独立开关，便于在端侧按实测瓶颈选择。
- **7B视觉剪枝迁移**：使用官方Qwen2.5-VL-7B-Instruct，按其窗口注意力与位置编码重建剪枝；FP32、280×392，ViT第16层后每帧对140组保留70组。不是把2B评分器权重直接套到7B。
- **历史收益头迁移与组合检查**：按7B特征维度重新训练713,537参数小头，比较内容可见、屏蔽历史内容及同读取量简单节点控制。保留问答成本，避免把Token更少直接写成更快。
- **训练验收与恢复工具**：剪枝使用实际硬选择路径验收，拒绝更新时同时恢复评分器与Adam状态；训练阶段比较、权重身份核验、逐答续跑与内容/格式分离均留下证据。执行可靠性不等于泛化提升。

## 2. 独立工程成本

6个来源，每方法4次轮换重复；表中为逐来源中位数相加。A800文件重放，不能外推Jetson实时性能。

| 方法 | 完整处理耗时/秒 | 相对顺序完整 |
|---|---:|---:|
| 顺序完整视觉 | 252.48 | 基线 |
| 预取完整视觉 | 220.87 | 减少12.52% |

## 3. 7B剪枝质量与训练收束

StreamingBench150题来自144视频；短片60题来自52视频，10—90秒。每题两个相关的选项排列，因此分母300/120不是独立题量。采用选项Token评分，选对答案内容计正确，不是开放生成或API解释评分。集合已打开用于开发/回归。

近期读取4帧对、8帧。LS是有界保存的近期和历史全部节点，**不是完整原视频历史**。完整视觉和剪枝保持相同帧对容量，分别140/70 Token每对；这不是相同Token预算的比较。

| 视觉方法 | SB近期 /300 | SB＋LS /300 | 短片近期 /120 | 短片＋LS /120 |
|---|---:|---:|---:|---:|
| 不剪枝 | 215 | 218 | 110 | 116 |
| 固定剪枝 | 209 | 210 | 105 | 113 |
| 免训练内容剪枝 | 209 | 220 | 102 | 110 |
| 内容起点残差训练 | 209 | 217 | 105 | 110 |

内容剪枝＋LS在SB上相对不剪枝＋LS多2次正确，视觉Token约减半；短片少6次正确。这支持将它保留为质量与成本取舍候选，不支持全面优胜。训练使用270视频2351题、一轮270次来源级提议，236接受、34拒绝，只有30个接受来源选点实际变化。训练后四格相对内容起点为0/-3/+3/0，来源聚类差值区间均跨零，因此没有替换免训练内容策略。

证据：`results/content-residual-eval-223984/analysis.json`，源码`source/7b-content-residual-*`。训练和评测来源按既有ID/SHA隔离，不声称已经排除未知转码母源。

## 4. 历史收益头与组合

| 条件 | SB /300 | 短片 /120 |
|---|---:|---:|
| 完整视觉＋LS | 218 | 116 |
| 完整视觉＋冻结可见头 | 220 | 112 |
| 内容剪枝＋LS | 220 | 110 |
| 内容剪枝＋原冻结可见头 | 213 | 106 |

直接把完整视觉银行训练的小头接到剪枝银行，出现特征/标签分布变化。头虽减少读入Token，选择开销使QA分项相对剪枝LS约慢19%/27%；这是共享视觉执行下的QA分项，不是独立端到端时延。详见`reports/剪枝与收益头组合.md`。

后续开发选点修补可达到SB224/300、短片106/120，但简单固定最后节点达到同样分数，SB全部300条内容答案相同。再用STAR扩大监督、改为收益差排序，三个种子开发成绩均复现联合读取，且可见头在全部203个开发问时选择全部历史；屏蔽历史内容同样达到该分数。**分数恢复并未证明学会了有用的节点选择**。这些是开发诊断，不作独立测试成绩；见`reports/收益头修订结果.md`及对应JSON。
