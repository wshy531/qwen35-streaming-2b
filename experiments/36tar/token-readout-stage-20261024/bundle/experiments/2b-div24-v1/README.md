# Div24：固定48→24五臂开发对照

持续进度只看项目《实验总纲.md》。源码/结果与旧实验独立，不修改模型默认核心。

方法为DivPrune论文Algorithm 1的Qwen3.5投影后适配：余弦距离矩阵，先选距最近邻最远的Token，再逐次选距已选集合最近距离最大的候选；并列取最低原始索引，最终按原输入次序排序。选择时归一化，输出保留原值、原位置与真实帧对时间。零向量使用eps=1e-12；不接收问题、答案或未来帧。不宣称最优子集或论文性能已复现。

参考：https://arxiv.org/html/2503.02175v2 （Algorithm 1）。作者仓库：https://github.com/vbdi/divprune 。论文算法已核对；作者仓库的CLIP编码入口并非本适配的直接实现，不称逐行复现作者代码。

五臂为full48、odd24、grid24、tome24、div24。grid24按6×8网格行列奇偶交错覆盖；odd24是旧奇数列控制。共同使用冻结的171＋98开发题与34中途查询，303查询、112来源协议组、1515答上限、12120生成Token上限。未更换视频、题目、选项和采样；争议长题单列。旧303均已打开，不是新来源验证。

该轮持有单来源完整特征档案，是压缩保真诊断，不是有界记忆部署。五臂同时档案在320对、2048维时张量理论上限379238400字节，逐来源释放；观察主状态仍用原48表示。共享准备与QA计时只作描述，不是五套独立系统完整速度。真正同384记忆组合之后单独测M0、原M2、A06、LS各自压缩开关。

本地CPU入口为preflight.py，显式设置CUDA_VISIBLE_DEVICES=-1。覆盖独立标量算法参照、零向量/相同值/并列、子集原值和坐标、档案上限失败不改变状态、全部1515布局、原48与既有读取器逐位相等、真实20帧/9次主编码/1次孤帧快照/10次微型问答及主状态隔离。无预训练权重或GPU。

analyze.py复用已修正答案解析：答案正确性为主，格式单列，全部成对纠正/损失、分组和缺答保留。freeze.py绑定CPU回执、协议、运行源码、标签和评分器SHA。无GPU_authorization.json不得运行真实GPU。

GPU候选脚本run_eval.sh：g078t/comment=gx_llm、1A800、4CPU、24GiB、60分钟，1次FP32载入、3981共享视觉编码；不训练、不下载、无自动重投。必须先完成远端一致性与CPU预检，再按超算规范取得本次明确许可。不能因本说明存在脚本就声称已经部署或获批。

bootstrap.py和build_preflight.py仅用于本次从冻结旧脚本构建独立版本；准备目录已存在时不得重跑bootstrap以覆盖记录。finish_preparation.py已用于本次计划修订，不应重跑以重复追加计划文字。正常复现直接使用已冻结源码与输入。
