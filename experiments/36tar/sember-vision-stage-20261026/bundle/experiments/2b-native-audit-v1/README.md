# 官方原生读取与流式续接审计

本目录回答一个优先问题：当前低分是否与我们的输入或流式改造有关。持续进度只读项目《实验总纲》，本文固定本实验协议。

## 比较结构

| 条件 | 模型实现 | 视频输入 | 用途 |
|---|---|---|---|
| A | 独立官方 Transformers 5.4.0，原 processor/generate | 仅提问前前缀；官方2 FPS、最多768帧；原保存的动态分辨率配置；不补边 | 正常视频读取控制 |
| B | 同一官方5.4.0 | 对齐本方0.5 FPS、288×384补边、完整帧对/时间戳/MCQ，不压缩；一次prefill | 与A比较输入协议整体差异 |
| B0 | 原官方5.3.0，未导入项目模型副本 | 与B完全相同 | 隔离官方软件版本更新，再与C比较 |
| C | 已完成218526完整流式续接参照 | 同B/B0 | 复用同题输出，不额外跑GPU |

增加B0是为了不把官方版本差异误算为输入差异或流式退化。5.3.0官方原视频四帧接口已在CPU随机微型模型上复现`get_rope_index`的StopIteration；官方5.4.0原视频接口通过，原环境未改。两版模型均不加载qwen35_local或streaming模块、不替换模型函数。输入构造可复用纯解码工具，不复用项目语言执行器。

所有组FP32、贪心、关闭thinking、最多16输出Token、MATH SDPA后端，与既有C的数值设置对齐。这是固定MCQ测评配置，不声称穷尽官方所有采样/精度/推理设置。A/B输入与帧数、分辨率同时变化，差异只归因于输入协议整体，不冒充单因素。

官方采样通过原视频处理器的`sample_frames`在截至提问的帧编号范围中产生；逐帧核实际PTS不超过提问截点。已选帧交给原processor时禁用二次采样。CFR12检查不通过时明确失败，不能猜时间。B/B0的待配单帧遵守原规则，仅真实EOF才允许补齐，完整前缀摘要与旧冻结清单相等。

## 固定预检与后续

先用8题型×3前缀长度桶固定24题、21来源，查询50—470秒；按题目SHA排序选择，未读取标签或已有成绩。该面板用于长输入接口、重大退化信号与正式478题资源估算，不承担完整能力排名。新GPU拟72正式答＋3预热、最多1200生成Token、3顺序FP32载入、75次视觉前向；60分钟、1A800、4CPU、24GiB，日志128MiB，无训练/数据下载/重试/requeue。当前未获得本次精确GPU授权，不得提交。

预检后仍以完整478题为目标；先按真实速度/显存估预算再批准正式运行。预检有重大不一致时先定位已证实问题，不在24题上调提示或筛掉失败题。超过GPU/内存/上下文边界保留工程失败，不悄悄截断或降质后当同输入控制。

## 隔离与复现

`prepare.py`固定名单；`probe_official.py`记录原生兼容成功/失败；`preflight.py`比较两个官方版本与当前stream的微型权重、输入和输出；`cpu_normal.py`检验短真实默认视频路径。原生版本环境只共享既有Torch等重依赖，官方transformers包置于独立环境，核源码路径/SHA，不修改原安装。

运行`run_profile.sh`前必须具备绑定冻结源码的明确GPU批准文件。每个条件独立进程；原生完整prefill后调用官方生成。保留原文输出和首次logits用于版本桥诊断，评分时正确率与格式分别统计。无答案/证据区间/原模型答案输入GPU worker。

依据：[官方模型卡](https://huggingface.co/Qwen/Qwen3.5-2B)、[官方5.4.0模型源码](https://github.com/huggingface/transformers/blob/v5.4.0/src/transformers/models/qwen3_5/modeling_qwen3_5.py)。软件包由PyPI版本和wheel SHA固定，不追随main。
