## 2. 实际改了什么

### 2.1 从固定48布局迁移到108布局

288×384画布经官方处理器产生18×24个视觉patch，空间合并后为9×12，即每对真实帧108个投影Token。旧192×256为6×8、48个Token。

旧实现中的节点上限、坐标校验、排序、位置推进和预算均含固定值，不能仅放大图像。新目录`experiments/2b-sember-v1`携带原网格，修改接口而不改已经验收的KV/卷积/递归计算内核。

```python
# 原始来源位置排序
key = source_pair_id * (height * width) + row * width + column
# 一段视觉内容结束后的位置推进
offset += max(height, width, source_last - source_first + 1)
```

原帧对仍由两个真实采样帧组成。中途剩一帧时等待；只有真正EOF才补齐一次。解码器可以内部读前，但未来帧不会提交视觉编码。0.5FPS、等比补边及官方MCQ提示固定；搭档采样率未提供，因此没有声称精确复现其输入协议或分数。

### 2.2 压缩与记忆规则保持固定

full保留108个Token；odd保留原序号1、3、…、107；change按与上一已提交帧对的同位置余弦变化保留54个，再恢复原坐标顺序。冷启动用odd；不调阈值或选择比例。

```python
score = clamp(1 - cosine(current, previous), 0, 2)
selected = stable_descending_order(score)[:54]
selected = sorted(selected)
```

压缩发生在完整视觉编码之后，**没有减少视频解码或视觉编码次数**。其直接目标是减少存储或问答读取Token；相同预算下则可保存更多帧对。

| 模块 | 视觉Token预算 | 规则 |
|---|---:|---|
| M0完整最近窗口 | 864 | 最近8对，每对108 |
| M0压缩、相同画面覆盖 | 432 | 最近8对，每对54 |
| M0压缩、相同Token预算 | 864 | 最近16对，每对54 |
| 原M2 / A06 | 近期432、开放108、闭合324 | 原规则和原深度优先选择分别保留 |
| LS | 近期432、共享历史432 | 容量允许时保留完整代表，溢出再合并 |

M2/A06压缩臂沿原分区运行，实际最高810Token，空余54没有偷偷填满。change另持有上一对完整特征884,736字节；事件描述子和质量/坐标张量也计账。因此同视觉Token预算不等于同总内存。

### 2.3 两种读取来源分开运行

有界进程只保存银行，不持有观察主KV。每次提问重新建立语言上下文，完成后释放。

`R_all_history_stream`则持续接续全部混合状态，提问时复制状态。这是使用同一预训练权重的完整流式历史参照，**并非未经修改的官方原生实现**。它与银行在两个顺序独立进程运行，不能藏在有界方法资源中。问答前后实际缓存或银行SHA检查通过；一致性审计耗时单列。
