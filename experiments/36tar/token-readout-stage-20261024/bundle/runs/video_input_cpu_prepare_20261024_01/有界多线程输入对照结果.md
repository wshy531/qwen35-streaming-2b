# 有界多线程视频输入：固定对照结果

日期：2026-10-24。持续进度以项目根目录 `实验总纲.md` 1.90—1.91 为准。本文件是本轮固定结果快照，不修改周报或综合汇报。

## 1. 结论

本机视频输入适配已完成。固定8个来源、两种配置、各两次重复的32个顺序独立CPU进程全部通过，运行窗口约13分29秒，没有失败重试。多线程配置在8个来源的输入处理上均较快，同时增加了解码并行和少量内存。

每个来源先取两次耗时的中位数，再分别相加：基线251.4135秒，多线程134.6340秒，减少46.45%，约1.87倍输入处理吞吐。**这是本机读取/解码/采样处理的收益，不是2B模型或完整问答流程提速46.45%。**

## 2. 做了什么及其原因

上一轮独立GPU成本对照中，读取压缩视频并解码成像素占用大量时间。旧实现明确使用单线程解码，之后才挑出采样帧，因此即使减少送入语言模型的视觉Token，仍需承担大部分文件解码工作。

本轮直接比较以下两种PyAV配置：

| 配置 | 解码线程请求数 | 线程方式 |
|---|---:|---|
| slice1基线 | 1 | SLICE |
| auto4候选 | 4 | AUTO |

线程数和线程方式同时改变，因此结论针对这组配置，不是只改变线程数的单变量结论。所有采样帧编号、真实PTS、192×256等比补边RGB、提问时刻及完整帧对提交规则均固定。不靠少看画面、降低分辨率或缓存全视频换取速度。

输入仍为：压缩文件 → 顺序解码 → 固定采样与补边 → 交付真实帧对。改动发生在最前面的输入层，模型视觉编码、Token选择器及记忆银行本轮未改。

## 4. 输入和资源核验

- 原清单共有2,958个采样画面，每个在两配置×两重复中各验证一次，共11,832次RGB SHA、帧编号和实际PTS检查，全部通过。
- 固定38个问题时刻，其中长视频34个；四次重放共152次查询边界检查。长来源逐查询的已接收帧、完整帧对提交、待配帧及提交前缀摘要与旧快照一致。
- 长来源按原协议到EOF；短来源到既有最后采样帧停止，保留显式孤帧查询补齐规则。不能把短来源的截止读取说成物理EOF。
- 应用待交付RGB最多2帧，低于3帧上限；没有保存完整RGB视频。内部解码参考帧/重排序/线程缓冲另计，不能说整个FFmpeg只缓存2帧。
- 全32次进程RSS高水位最大值：基线108,359,680字节（103.34 MiB），候选123,265,024字节（117.55 MiB），增加约14.21 MiB，均低于1.5 GiB守卫。两边最大值未必来自相同case，不把差值当逐case恒定开销。
- 进程总线程观测最大值：短源基线4/候选8，长源基线6/候选8。请求4个解码线程不等于整个进程只有4线程，也不代表总CPU工作量已测得下降。
- 取消、单次消费、RGB清理预检通过；另以真实共享`FramePacket`和`FrameWindow`完成长/短入口×两配置的4项非计时适配检查。没有模型推理验收。

## 5. 测量适用范围

本机环境为Windows 11、Python3.12.14、PyAV16.1.0、32逻辑CPU。CUDA禁用，没有导入Torch、加载模型、使用GPU或连接集群。

每次先计算媒体SHA，会预热操作系统文件缓存，故本轮不是冷盘测试。每个来源仅两次重复，用AB/BA顺序平衡，不作为统计显著性或跨设备泛化结论。

首采样延迟从打开/解码开始计，不包含前置SHA。总体来源中位数约0.043→0.035秒，但实际monotonic计时器为GetTickCount64，粒度约0.015625秒；短源中位数反而约0.016→0.023秒。因此本轮**不主张首帧延迟稳定改善**。整段秒级墙钟才是主要时间证据。

解码器内部为压缩依赖而前读，与向模型交付未来画面是两回事。本轮核对了交付/提交边界，没有测1倍速墙钟播放、实时摄像头或端侧负载。

本机与历史A800所在CPU、系统和输入执行环境不同，不能将本轮46.45%直接代入历史GPU总耗时，不能据此生成新的端到端加速数字。输入像素相同也不代替完整GPU推理回归。

## 6. 实现与后续决定

代码在`experiments/video-input-cpu-v1/`：`source.py`为惰性有界来源，`consume.py`检查查询边界，`worker.py/run.py`管理守卫及顺序进程，`analyze.py`审计结果，`integration.py`提供显式可选接入。

核心配置为：

```python
context.thread_count = 4
context.thread_type = 'AUTO'
```

可选接口为：

```python
source = long_source(env, path, group, decoder_config='auto4')
packets = short_packets(env, path, group, decoder_config='auto4')
```

`group`必须包含固定规范输入清单。这不是任意视频采样入口，也未修改旧冻结GPU基准或默认演示入口；以后使用时需显式选择并重新冻结依赖。Decord未安装，本轮没有下载安装或另开库对照。

本轮按预定一次对照收尾，保留auto4作为已通过本机输入核验的候选，不追加线程数或采样参数扫描。下一次需要模型成本验证时可优先采用并冻结这条输入路径，但仍须在目标集群验证，不能声称已经部署。

STC-Cacher是下一模型侧候选槽，针对视觉网络内重复计算，与本轮视频文件解码分开。已只读核到本地2B视觉层的成对时间patch、融合QKV、24层1024维结构和后置merger；尚无缓存实现或收益。进入该槽时应先做一个最小缓存/刷新方案的CPU接口核验，维持输出48Token与记忆算法不变，再按固定303问题/六长来源设计完整视觉对照并另行申请GPU；一轮后分析收尾，不同时追加其他选择器。35自然来源59候选题的准入审核仍待完成，本轮没有把它们宣称为新测试集。
