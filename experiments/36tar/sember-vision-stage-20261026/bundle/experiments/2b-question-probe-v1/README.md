# QProbe24：问题到达后的视觉读取筛选首版

这是独立研究候选，尚未默认启用。持续进度以项目 `实验总纲.md` 为准。

前轮 E2 固定银行完整保存，但简单 odd 删半读取仍造成退化。本段检验一个不同假设：已知问题后，以早期语言注意力评分选择视觉特征，能否保留更相关的信息，同时仍节省回答成本。

来源是只读资料 `Token压缩.md` 的 FastV 段，以及 [FastV 作者代码](https://github.com/pkunlp-icler/FastV)。本实现不是原版 FastV：不在深层继续被裁剪的隐藏状态，而是一个短探针后，从选中的原投影特征重新建立完整问答上下文。也不是旧 Q4 逐节点条件似然评分的新名称。

```
真实帧对 → 原48视觉投影 → 原LS384有界银行（写入规则不变）
                                      ↓ 问题到达
             完整银行＋问题 → 前3个GDN层 → 第4层入口Q/K评分 → 退出并释放
                                      ↓ 每节点保留一半，恢复原顺序
                    原投影特征 → 全新完整语言问答 → 逐Token输出 → 释放
```

Q/K评分采用原 q_norm、k_norm、GQA、部分RoPE及因果规则。只对实际问题文字（包括用户提供的选项）计算注意力行，按16行分块；分母包括全部因果可见文本和视觉key，不只对视觉列归一化。固定每个节点保留一半，避免同时改变历史来源覆盖和时间标签。相同分数按原顺序打破平局。不把注意力解释成已验证的语义相关性。

前3层探针不建立持久混合缓存；评分在第4层注意力模块真正前向前退出，不计算该层V、输出、MLP及后层。临时hook在成功/失败时均移除。探针不读取答案标签，也不利用尚未到达的问题影响银行写入。重新读取仍有代价，QA总时间必须包括完整上下文构建、探针、选择、第二次构建、prefill及生成。

固定对照：LS完整48、LS简单odd半读、LS问题评分半读；112来源/303已打开开发问题时刻，主269/长视频支持16/人工6分别统计，正确性和格式分报，606条旧完整/odd生成与输入必须复现。若主269和支持16相对完整均无净损失，至少一层相对odd净恢复，并且完整QA累计时间下降15%，才申请M2/A06组合和搭档新冻结数据确认。否则关闭首版，不扫层、公式和比例。

CPU预检使用随机微型权重，不能说明真实识别能力或A800速度。`preflight.py`检查评分数值、因果屏蔽、GQA/RoPE、提前退出、故障释放、旧LS存储及全部909布局；`tiny_session_check.py`检查7个真实采样帧、5次微型问答、继续写入和EOF边界。

`run_eval.sh`和`evaluate.py`只用于另行明确批准的单次GPU任务；没有与执行锁匹配的授权文件会拒绝启动。源码冻结后不修改；禁止自动重试。不训练、不下载、不更改旧报告、旧实验或默认模型核心。
