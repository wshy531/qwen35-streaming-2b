# A06闭组深度优先首版：真实流式对照结果

2026-10-21回收与分析；作业217786在10月20日提交，使用当时冻结的协议与六段视频。持续进度、后续候选与授权仍以项目根目录《实验总纲》为准；旧综合汇报不修改。

**结果：结构目标部分实现，有两道位置题改善，但两道重点顺序题没有修好，尚未得到远期记忆能力提升的证据。** 本首版保留为可复现候选，不升默认，不继续扫描深度或排序参数。

## 为什么做这个改动

前轮发现：商店和施工顺序题在未压缩旧范围中能答对，压缩后答错。保存下来的真实节点还显示，商店一棵根最深47层；施工一个输出Token汇聚了4679/5376个原始Token贡献。

这里mass是原始Token贡献计数，不是注意力或丢失信息的百分比；正确题也有集中。不能仅凭这些统计宣判唯一根因。本轮只验证一个假设：少让旧根反复承接合并，能否改善读取。

## 改了什么，控制了什么

原闭组选择规则按既有复合代价取相邻根；A06首版改为先比较父深度，再用原代价和索引破平局。它是局部深度优先策略，不是保证全树最平衡的算法。

近期4对完整特征、开组48、闭组144的总384视觉Token不变；视觉编码、融合公式、因果事件标志、原读取位置规则、问题和权重都不改。每个真实帧对只编码一次，同一投影更新三组银行。一套原混合观察状态继续接收新画面，问答分别在独立新上下文读取银行，逐Token交付后继续观察。

没有完整RGB/未压缩特征历史档案，没有把问答结果写回观察缓存。问答没有使用未来帧或未提交的孤帧。主状态重置与银行保留分开管理。不同合并次序会连带改变节点分区、特征、时间文字和坐标；所以这不是只改树高而其他输入逐位相同的数值干预。

## 树浅了，为什么早期证据仍可能读不好

在34个相关查询截点，闭组最大深度的总体最大值从47降至26，截点中位数从27降至17。这些是同六视频的相关观察，不能当34个独立来源。

两组的合并总次数相同，变化是合并如何分布在各棵根上。树浅不代表少做了压缩，也不代表总计算变少。

但树深不是历史细节分辨率。以输出前记录的全部六组人工见证做来源分配审计：

- 商店题：原M2用两个根共96Token覆盖相关185对范围；A06用一个48Token根覆盖198对。最深路径从47变17，但相关旧内容被放进更少Token。
- 施工题：关键旧范围原来112对压48Token，A06变为171对压48Token；该关键根深度只从19变18。全森林的最大深度下降，并不等于目标证据得到同等改善。

可以理解为：装订层数减少了，却把更厚的一摞历史塞进同一页。这里是节点来源范围/预算的描述，不能单独证明某条信息一定消失或解释全部错误。其他正确题也出现更大范围压同一根，因此不能由这一指标直接判定答案。

本轮没有保存新银行逐Token mass张量，不能声称79.7%或87.0%的集中已被改善。权重集中、压缩内容、位置适配与时间分区仍不能完全分离。
