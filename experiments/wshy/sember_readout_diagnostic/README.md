## 要区分的问题

1. 重复选项标签是否影响回答：修复后的纯文字与已锁定旧纯文字逐题比较。
2. 把作者标注的证据直接给模型，不经过记忆压缩，模型是否能利用证据。
3. 同一证据经过原模型读取和当前外部特征读取，回答是否不同。
4. 不使用长短期记忆，原模型读取完整因果前缀是否优于当前结果；与证据片段
   对照的差异也可能反映历史干扰、上下文长度或证据区间不足，不能单因果归因。

## 固定四组，102 道题全部进入

- `text_only_clean`：当前流式模型实现，空视觉输入，修复后的提示词。
- `native_prefix`：仓库根目录 `qwen35_local` 原始模型，一次完整前向读取从
  视频开始到提问时已经形成的所有完整帧对，不使用记忆银行、压缩或检索。
- `native_evidence`：同一原始模型，只读取作者标注区间命中的完整原始帧对。
- `current_evidence`：同样证据帧对逐对编码，使用现有外部特征拼接、位置规则
  和 512-token 分块预填充；所有节点为原始节点，不做合并或 token 压缩。

新答复最多 408 条，每条最多 8 token，总生成上限 3264 token。旧纯文字
答复从 SHA 锁定的既有文件读取，不重新生成。原始实现与流式实现各载入
一次，依次运行，不同时驻留；总计最多两次真实权重载入。

原生输入沿用已审计历史基线的位置接口兼容层：处理器为每个时间组生成视频
标记，调用原模型 `get_rope_index` 时展开对应的时间组网格；视觉编码仍使用
原来的完整视频网格。**这不是完全未经适配的 Hugging Face `generate`**。
权重不训练或修改，原模型组不使用 M0/M2/A06/LS、外部特征注入或跨问答缓存。
原生与当前读取的比较包括模型实现、时间戳文字、位置构造及预填充方式；
若出现差异，本实验先定位到整条读取链路，不直接声称某一个模块有问题。

## 输入与比较边界

- 沿用已下载的 18 个视频、102 道官方原题、既有 1 fps 采样清单。
- FP32、192×256 letterbox、贪心解码、关闭 thinking，提示词统一修复一次
  标签重复；不改变选项内容、顺序、答案或原始数据文件。
- 所有组仅使用提问前完成的全局帧对，奇数尾帧仍挂起，不复制补齐。
- 证据选取使用作者区间：一个帧对只要至少一帧命中区间，就完整保留该对。
  保留区间边缘的另一帧是为了避免改变原始时间分组，并逐题记录。
- 作者区间不是人工确认的充分证据。没有完整帧对命中时，两组证据控制明确
  标为不可执行，不回填邻近帧、不算成正常错误答案。仍保留在 102 题清单中。
- 最大 300 帧对 / 20000 输入加输出 token。超出即停止；不偷偷截短历史、
  降采样或只保留能装下的题。证据特征保留是离线诊断，不宣称满足流式常驻预算。
- 每次问答创建、释放独立语言缓存；检查 RNG、模型位置状态和证据节点未改变。
- CPU 对每题核对真实 RGB/PTS、原生与逐对预处理张量逐元素相等、原生时间戳
  与真实 PTS 偏差不超过一帧；GPU 复核张量 SHA、位置 SHA 和视觉编码次数。
- 正确答案只在独立评分阶段读取。模型只接收问题、选项、像素和时间戳；
  使用作者区间选择片段本身属于 oracle 信息，不能作为流式方法成绩。
- 只报告答案内容正确数、未解决条目、逐题修正与退化；不报告格式指标。
  无明确选项的回答保持待人工复核，不直接认定语义错误。
