# 容量与时间片保留的单轮开发对照

已有诊断发现：部分旧顺序在未压缩时能答对，合并成少数节点后答错；降低树深没有恢复它们。因此本轮分别检查“预算太小”和“不同时间过早混合”。这仍是待检验的解释。

固定五组：M0近期窗口384/768，原M2森林384/768，S24森林384。S24保留近期四对的完整48 Token；旧画面先在每对内部48→24，用相同总预算容纳更多旧时间节点。它没有取消跨时间合并，空间细节也可能受损。事件判定、模型和读取方法保持一致，不混入A06。

六个旧开发来源、全部34次中途提问，共170答；每对只编码一次。先分析容量四组，再比较同384的S24。原28题、画面支持16题和人工延迟6题分别报告；格式错误保留。CPU契约不说明真实模型回答质量，既有原生结果仅作历史参照。

`freeze_compare.py`冻结输入与源码；`check_compare.py`核验170布局、真实16帧和五次随机微型问答。`transport.py`只部署小文件和进行CPU预检，不能提交作业。`run_eval.sh`仅在本次GPU预算另获明确批准后运行：1 A800、4 CPU、24 GiB、30分钟、g078t/gx_llm，最多170答/1360生成Token/1426次共享视觉编码/1次载入。不训练、下载或自动重试。

这是因果重放和中途逐Token回答，尚非1倍速墙钟播放；不是新留出集或20来源160题正式验证。14段额外素材的概览资格审核与本轮六源试验分开记录，概览不能直接产生已验证问题。持续状态只见项目`实验总纲.md`。
