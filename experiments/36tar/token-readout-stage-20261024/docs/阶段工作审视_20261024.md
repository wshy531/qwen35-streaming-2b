# 阶段工作审视

核对日期：2026-10-24。本文件是一次审视快照，持续进度只在`实验总纲.md`维护。依据已保存的架构、数据目录、逐题分析与成本回执，本次未启动模型、GPU或新算法实验。

## 总体判断

项目已建立有实际内容的流式推理原型，近期也取得了局部存储和语言读取成本下降。但尚未形成经过新来源独立验证、同时保住关键回答质量的长期记忆或Token压缩方案。V1视觉缓存首版没有收益。

从架构学习目标看，核心链路已具有学习与复现价值；从论文目标看，目前主要是研究平台和开发证据，核心效果与泛化证据仍不足。我的工作顺序需要纠正：对既有开发集合追加比较较多，严格记忆需求、新来源和独立复核补得较慢。

## 1. 实际做出的系统

| 工作 | 具体内容 | 已能支持的判断 |
|---|---|---|
| 模型内部续接 | 接续注意力KV、卷积与Gated DeltaNet递归状态，处理多Token新增块 | 已有固定条件下的数值、隔离、重置及真实运行证据；不是每块重新完整问答 |
| 增量视频会话 | 真实帧对编码、时间/空间位置衔接、观察状态与问答分支隔离 | 新画面可继续进入；问答后丢弃分支，不自动保存跨轮聊天 |
| 有界运行 | 容量重置、记忆起点、有限输入缓冲和丢帧记录 | 能管理资源边界；不等于无限记忆或任意输入均正确 |
| 2B与集群接口 | 迁移并验证2B运行桥接、FP32参考、固定评测与Slurm资源管理 | 当前2B真实运行成立；0.8B历史不冒充2B结果 |
| 外部视觉银行 | 有界近期窗口、事件森林、深度排序、共享历史池，独立语言上下文读取 | 可以在独立预算下保存和读取历史；不保证压缩后细节可恢复 |

近期用于比较记忆/压缩的bank-only路径不长期保存观察主语言KV。它有利于隔离银行证据的作用，但资源口径与持有观察主状态的完整系统不同，不能直接横比。

这些改动主要改变推理结构、状态和表示，没有重新训练权重，也没有使基础识别能力天然增强。近期2B实验是因果快速文件重放，尚非端侧1倍速或真实摄像头验收。

## 2. 数据工作及其效果

2026-10-21目录快照：182个视频文件、约5.53小时，其中155个不足3分钟，最长10.22分钟；519道官方候选题加人工题/重复截点形成528个题目—时刻条目。这些是资产数量，不能当成全部合格独立题。

近期固定对照使用112个来源、303问题时刻：67来源171题、T批39来源98题、6长来源34次查询。主269题按事实82、时序127、因果60分组。原题、原标签、媒体/采样SHA、实际PTS和提交前缀均保留，这使回归和失败诊断可复查。

主要不足：

- 6个长来源不等于34个独立长场景；28个官方长题仅16个支持、11个歧义、1个截点未建立，另6题为人工开发题。
- 原视频长，不代表问题必须用长期记忆。既有复查中，支持16题有14题列出的见证距问题不超过4秒；这只是已列见证年龄，也不能替代全部充分证据审核。
- 1/0.5FPS及192×256输入可能漏掉短动作、小物体或颜色线索；原视频可答与实际输入可答需要分开确认。
- 内容复核以单助手为主，独立第二人复核不足；303时刻已反复用于开发，不能再承担未见测试。
- 已盘点35个自然来源59候选题，但实际内容审核和可认证未见均为0。它们是待审核库存，不能写成新测试集已经完成。

这些数据目前更适合工程回归、算法开发和机制诊断，尚不足以证明稳定的长期记忆提升。我此前多次把新来源审核排在算法实验之后，使这一缺口持续存在。

## 3. 长短期记忆的结果

以下为同一轮固定比较的内容正确数，方法间使用相同384视觉Token预算；各自其他状态仍需单列计账。

| 方法 | 主269 | 长视频支持16 |
|---|---:|---:|
| M0近期窗口 | 156 | 10 |
| 固定蓄水池 | 158 | 12 |
| 原M2事件森林 | 161 | 9 |
| A06深度优先 | 164 | 11 |
| LS共享历史 | 166 | 12 |
| LS＋深度优先组合 | 158 | 11 |

A06改变必须合并时的顺序；LS延迟压缩并共享历史预算。在本开发比较中，LS/A06比M0多答对一些题，但LS在支持长16上与简单蓄水池同为12，没有证据说明复杂森林已成为必要机制。

组合将提问时最大树深从60降至19，却比LS少8题（7纠正、15损失）。这得到一个明确的有限结论：树浅不是记忆更好的充分条件，这版组合不值得升级默认。

目前没有充分证据证明这些方法可靠保留了很早且不再重复的关键事实。完整历史在上下文容纳范围内往往拥有更多证据；有界记忆的合理比较目标是质量—成本权衡，而不是预设必须超过不受同样预算限制的完整历史。

## 4. Token压缩做了什么

投影后压缩将每对48个2048维特征变成24个。比较过固定odd/grid选择、ToMe式加权融合、Div多样性选择、纯变化change、空间与变化混合mix，并完成M0/M2/A06/LS的压缩组合。

有限档案保真比较中，full/odd/grid/tome/Div主269为164/162/161/158/159；change在随后同预算比较中对odd为167/162，但小幅开发差异的不确定性跨零，长题仍有退化。这些不是无条件默认升级的证据。

回接有界384Token银行后，完整48/change24主269分别为：M0 156/155，M2 161/161，A06 164/161，LS166/159。扩大覆盖没有带来稳定收益。投影后ToMe也只是本适配，不是其论文所有设置。

同最近8对覆盖的进一步控制中，full/odd/change为156/152/159，但支持长16为10/7/7。change的主集信号与长题退化必须同时保留，不能只展示总分增长。

独立成本验证确实取得局部收益：change回答阶段91.53→53.17秒，减少41.91%；银行及必要选择器3.01→1.88MiB，减少约37.5%。可是全工作量只减少4.53%，六长来源全链约0.17%差异，整体显存仅少约20.57MiB。视觉编码仍完整运行，压缩不能减少那部分成本。

因此，压缩已引入真实推理路径，也有资源收益，但目前缺少同时满足关键质量、完整成本和新来源验证的默认方案。

## 5. 最近两项工作

V0是输入工程：限4线程AUTO与单线程SLICE比较，本地8来源32进程，采样/PTS/查询边界一致；输入累计中位数251.41→134.63秒，减少46.45%，最高RSS约增加14.21MiB。它使用更多CPU并行，属于本机这组素材的输入改进，不是模型算法或整段问答快46%。

V1在视觉层内部缓存每层K/V/注意力输出/MLP输出，每2帧对刷新，其余更新25%位置；Qwen融合QKV、RoPE和成对时间patch已实际适配。输出仍48Token，额外参考72MiB。

V1真实结果为主269均156（11纠正、11新增错误）、支持长16从10降8；视觉90.57→96.85秒，慢6.93%。原完整视觉303参照零漂移。当前无CUDA graph首版的局部少算没有抵消索引、分段投影、缓存复制和调度开销；没有逐kernel实验，不能断言某项是唯一原因。这一首版已关闭调参，不代表整个缓存方向被否定。

## 6. 我需要纠正的工作方式

1. **目标收敛不足。** 有界记忆、表示保真、视觉加速、输入工程都有关联，但同时推进后，项目缺少一条已在新来源上验证的核心主张。
2. **新数据与独立审核落后。** 同303时刻积累了大量比较，却反复延期最关键的验证基础。SHA一致证明记录可追溯，不能替代答案可靠和长期记忆必需。
3. **成本判断较晚。** 独立全链测量才量化了解码大头；用户提醒后才把既有输入资料落地。V1也应先用真实代表性帧对检查成本门槛，再投入全量质量比较，而不能把理论少算当作实际更快的充分动机。
4. **归因工具准备不完整。** 早期压缩日志缺所选索引/分数，后来只能提出镜头运动等解释，不能直接定位被删证据。下一段应按核心假设预留最少必要日志，不事后无限补诊断。
5. **工程证明讲得过重。** CPU通过、生成复现、分支隔离值得保留，但它们主要排除实现错误，不应在汇报里替代效果进步。
6. **研究目录与主交付仍有距离。** 多个独立目录便于复现，也增加使用与协作负担；有证据的稳定接口和实验候选需要明确区分。总纲历史快照也过密，不能让旧入口覆盖现状态。

没有本项目的新训练、2B在目标端侧设备的实测、小时级连续能力结果，也没有完成KV量化。这些不应通过“候选”或“已准备”表述成已经具备的能力。

后续性能候选先过真实权重的小规模成本门槛，再做全量质量比较；需要部署结论时才做独立全链和目标设备测试。当前不立即添加新模块，也不再扫描已结束首版的参数。
