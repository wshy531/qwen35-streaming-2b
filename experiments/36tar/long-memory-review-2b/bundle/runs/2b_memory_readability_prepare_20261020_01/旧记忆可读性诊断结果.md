## 两道顺序题：有支持压缩读取损失的证据

商店题的正确顺序是先看盒装玩具，再经过Duracell电池陈列。未压缩的旧范围回答A，压缩节点回答B，即顺序反了。

施工题的正确顺序是橙色搅拌机→蓝桶→抹板。未压缩的旧范围回答D，压缩节点回答A，即抹板→蓝桶→搅拌机。

这两题在加上完全相同的近期四对后仍分别保持原答案。因此，本轮不支持“旧节点其实能读，只是近期画面把答案干扰错了”作为它们的解释。原始特征可答、压缩节点不可答，支持优先检查当前合并表示与读取位置适配。

**还不能把原因全部说成特征平均。** 未压缩节点与压缩节点的数量、时间组织和幸存坐标布局也不同。本轮定位的是“压缩后的表示及其适配组合失效”，没有单独隔离所有因素，更没有证明平衡合并一定能修好。

## 布颜色题：不能把所有错误都算给压缩

正确答案为红色。选定旧范围的未压缩输入答绿色，压缩节点答白色；两者加入近期画面后都不变。只有全部未压缩历史答红色。

这说明该题存在选取范围或上下文组织有关的读取问题，当前无法进一步区分视觉识别、时间指代与完整上下文的作用。不能把这题也计为“A正确、B错误”的压缩新增损失，不继续为这一题追加提示变体追分。

其余三题各条件均正确。这不证明它们一定依赖新增长期记忆：上一轮近期窗口也答对了它们，旧证据必要性仍未建立。

## 流式来源的CPU配套结果

同一真实视频前12秒，正常条件交付12帧、丢0帧；人为让每次问答耗时2.4秒后，采集仍发布相同12帧，交付8帧、丢4帧。完整来源指纹一致，队列最大只有1帧，问答期间采集继续，没有堆积。最大查询观察滞后分别约1.5秒和3.5秒，说明丢帧之外还需要显示回答陈旧度。

另有6真实帧/3问答的随机微型模型检查，以及4项故障/取消/截止调度契约。这些只是短窗口CPU工程证据；本次真实2B诊断仍是因果重放，不是八分钟1倍速墙钟播放，不报实时吞吐收益。

## 本轮结束后的建议

1. 收束这次36答诊断，不追加问题措辞、阈值或节点组合扫描。它已支持一个明确优先级：先处理合并后顺序信息的可读性，暂不把近期干扰当主要原因。

2. 按既有A06队列，先做一个有界CPU可行性段，核验更均衡的合并组织能否在同一384总视觉Token预算内实现。所有为平衡而保留的中间节点必须计入持久内存，不能保留全历史再假装在线；不能实现公平控制则说明阻碍并收束。可行时才固定一个首版与M0、原M2比较，不因本轮定位就宣称其有效。

3. 六题只用于开发回归，不代替正式长集。至少20自然来源/160有效题目标仍未完成。现有剩余14段超过5分钟的媒体仅有HLD/ASI官方题、没有EPM历史题；这是头信息盘点，不是画面准入。下一数据工作需明确重新标注或补充来源，逐题记录截点前见证、历史跨度、近期/旧细节/顺序等类型；不能直接把文件数量当成合格长记忆题量，也不能把它们冒称未见来源。

4. A04长短分配/384与768两档对照仍排在A06首轮比较或明确不可行结论之后；Q4问题相关读取不由这六题淘汰，但本轮B与D完全同答，没有支持优先上它。下一候选审视必须给出其具体验证位置，不能无限搁置。真实2B的1倍速播放也仍欠独立预算与质量/丢帧实测。

**此次成果是定位证据，而非模型优化成绩：我们从“森林没变好”推进到了“两道可答顺序题在压缩表示读取时丢失，近期混入并未新增错误”的可操作结论。** 下一项改造必须用真实对照验证能否修复这些损失，并检查是否伤害原本正确的问题。
