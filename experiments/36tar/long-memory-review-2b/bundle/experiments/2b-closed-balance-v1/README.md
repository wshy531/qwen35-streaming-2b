# A06首版：减少闭组旧根被连续重合并

持续进度与实际结果只看项目根目录《实验总纲》。本目录是独立首版候选，不改默认路径或旧综合汇报。

## 从真实失败中查到了什么

前轮同源未压缩旧内容5/6、压缩节点3/6，加入近期内容没有改变六条生成；完整未压缩历史6/6。新CPU审计只读取已捕获的真实节点，没有产生新模型答案。

- 商店顺序题的一棵旧根覆盖81对画面，深度47，最大一个输出Token的mass为3100/3888，约79.7%。
- 施工顺序题的旧根覆盖112对画面，深度19，最大一个输出Token的mass为4679/5376，约87.0%。
- 全部被指定读取的7个旧节点都属于已闭组森林。因此，只平衡“当前开放事件”未必改到这些失败所在部分。

mass是累计原始Token贡献计数，不是注意力分数，也不是语义重要性；87%不能解释成“丢失了87%的信息”。正确案例也有很集中的mass，所以它不是充分原因。

旧合并按特征相似度把多个源Token加权平均到目的Token，只保留目的坐标。可以类比把多个时刻的画面揉成混合笔记，再标上来源时间范围。范围存在不代表仍能读出各个动作先后。它也不是专门训练过的事件摘要器。

## 只改什么

仍为近期4对×48 + 开组48 + 闭组144 = 384视觉Token。仍用原因果事件标志、原合并公式和原位置读取方式。

闭组预算溢出时，从相邻根中选一对合并，原规则为原复合代价最低；本首版改为按以下元组取最小：

```python
(1 + max(left.depth, right.depth), old_penalty_total, adjacent_index)
```

先考虑合并后树深度，再用原内容/历史合并计数/时间代价和位置打破平局。没有调权重、改提示或更换压缩公式。这是局部深度优先策略，不是数学上保证整棵树最平衡的算法，也不保证mass均匀或保住事实。

实现不保存子树或完整历史，新增持久字段仅为标志和计数。原选择器兼容模式用于逐步核验复制的适配器没有引入其他变化。

## 对照如何运行

复用6段真实自然视频和原34个查询时刻。每个到达的真实帧对只编码一次，同一投影更新M0、原M2和A06。原M2的因果边界由共享的当前真实特征计算，A06读取同一标志；不从未来视频或答案推导分组。

保留一个共享2048Token观察主会话，查询时三组分别在独立新语言上下文读取各自银行，逐Token交付答案，随后继续输入。问答不改观察缓存或银行。没有为候选保存未压缩全历史，容量重置也不清掉外部银行。共享主状态/模型/临时问答分配必须计入整进程资源，不把多个银行的共享进程耗时当作独立提速比较。

全部28个原题保留；其中16个画面支持题单列，11歧义/1未建立问题继续保留而不混称干净准确率；6个人工延迟开发题另列。不只挑两道失败。原生完整历史沿用217776已有结果，不冒充本轮重新运行。
