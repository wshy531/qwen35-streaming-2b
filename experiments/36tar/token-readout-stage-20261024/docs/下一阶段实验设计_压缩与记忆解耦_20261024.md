# 下一阶段实验设计：分开管理保存成本、读取成本与输入成本

设计日期：2026-10-24。本文是审视和实验方案快照，不是实验完成报告；持续进度以《实验总纲》最新编号节为准。数据建设、内容标注和新测试来源由搭档负责。本方案没有提交 GPU、改动旧冻结实现或修改综合汇报。

## 1. 当前判断

已有流式状态管理和实验结果有价值。当前问题是三个研究目标被交替推进，而每轮后的决策没有充分收敛：

1. 同样的画面，用更少 Token 让语言模型读取，能省多少回答时间、损失多少内容？
2. 银行容量固定时，用压缩表示多存一些历史，能否改善回答？
3. 优化文件输入或视觉编码，能否让整个处理过程更快？

三者都合理，但改善其中一项不会自动改善另外两项。后续必须分别设定保存预算、读取预算、时间覆盖和计时边界。此前的 303 个问题时刻已是开发与回归集，继续在它上面做一次新机制诊断有意义，但不能把反复测量当作新的泛化证据。

## 3. 对先前推进逻辑的修正

### 3.1 更快的输入不会修复压缩造成的错误

V0改变视频文件如何解码，不改变交给模型的画面。它不会把change24已丢掉的细节补回来。因此下一成本实验不能以“解码改好了”为理由重新宣称压缩质量待定或忽略旧失败。

### 3.2 固定384 Token，不等于回答负担减半

把每对48 Token压为24后，如果银行依旧装满384 Token，只是容纳的帧对变多，问答仍可能读取约384视觉Token。时间标签也可能增多。此前P3主要研究这种固定容量组合；它不能直接证明省了一半回答计算。

### 3.3 需要更早设置实际成本门槛

V1减少局部计算行数，却增加真实时间。在下一个内部算子候选中，应先做代表性输入的真实计时，再决定是否展开全量能力评测。不能只凭FLOPs或理论复杂度决定大规模实验。

### 3.4 已经出现的失败足以限制默认使用

小样本不能证明所有压缩无效，但已观察到的错误足以否定“确认无损”这一说法。不必先证明错误的唯一根因，才能决定暂不默认启用。机制诊断必须能改变设计或决策，不能无限解释每个错误。

## 4. 实验一：结清V0与现有Token压缩的独立成本

**问题：采用已验证的auto4输入后，现有压缩还能够节省多少回答成本与整段处理时间？** 这是工程收尾，不是新算法能力实验。

### 固定设置

- 复用V0八来源、38个问题时刻：六长来源全部34次提问，另两短来源共4次。清单来自`runs/video_input_cpu_prepare_20261024_01/inputs/`，不可按算法表现替换。
- 三组：`auto4 + full48_8`、`auto4 + odd24_8`、`auto4 + change24_8`。全部保存相同最近八对画面；full最多384视觉Token，两种压缩最多192。完整视觉编码不变。
- 每组两次完整计划重复，共六个顺序独立进程/模型载入；第一轮按full→odd→change，第二轮反序。重复是为观察计时波动，不当作独立能力样本。
- 各方法独立完成解码、视觉、银行更新和问答；不共享视觉结果，不缓存整个视频。模型、精度、CPU核数、线程限制、问题、生成规则和采样保持一致。
- 每进程固定预热后清空状态。总预算草案：正式228答，加六个预热回答最多234答、1872生成Token；视觉调用以CPU枚举冻结为准，暂设总上限10,000次。

### 计量和结束条件

1. 逐题与既有同方法结果核对输入、节点和生成ID。发生差异先记为工程回归失败，停止评分结论；不通过改标签或放宽解析规则消除差异。
2. 分报从问题到达到首Token的时间、完整回答时间、文件处理墙钟、解码/视觉/选择/prefill/生成分项、CPU使用与RSS、GPU allocated/reserved、银行和临时问答缓存。嵌套分项不相加；首Token指标必须说明是否包含输入积压，本实验默认不含墙钟积压。
3. 各来源、六长来源与整体均报告两次原值和配对差异。两次重复不足以支持稳定统计显著性；若方向变化或收益小于观测波动，结论为未确认收益，不追加重复直到变快。
4. 不将本轮auto4秒数与历史slice1秒数拼接计算V0的集群收益或交互作用。此轮只比较同auto4条件下的压缩。若将来需要交互作用结论，应另设计同时期2×2对照，当前没有必要增加它。
5. 无论速度结果如何，已知长视频退化保留。实验结束后冻结成本结论，不再同配置追加全303计时。不能据这38题升级压缩默认。

**拟资源上限：** g078t、comment=gx_llm，1张A800、4CPU、24GiB、60分钟、日志64MiB；六进程顺序运行，不训练、不下载、不自动重试。估计不是提交授权；准备脚本和本地/集群接口预检后，再请求本次明确GPU批准。SSH未恢复不影响本地准备。

## 5. 实验二：把保存记忆与压缩读取分开

**唯一主要假设：在不改变银行保存内容及演化的条件下，只压缩交给语言模型的视觉Token，可以获得有用的回答成本—质量折中。** 这是待验证假设，不宣称一定改善质量。

### 改造位置

此前P3的路径：

```text
每个新帧对 → 完整视觉特征48 → 压为24 → 更新银行 → 用银行回答
```

本轮候选：

```text
每个新帧对 → 完整视觉特征48 → 按原规则更新银行
                                         ↓ 到达问题时刻
                                  导出同一份银行节点
                                  ├→ 完整读取（参照）
                                  └→ 临时选择一半Token后读取（候选）
                                         ↓
                               释放问答分支，原银行不变
```

“完整48写入”不意味着无限保留全部历史：M2/A06/LS仍按原384预算淘汰或合并。我们只取消新增的入库前48→24选择，让记忆算法使用其既有输入。

### 为什么先选简单选择器

沿用既有odd选择思想：每个导出节点按原顺序保留交错一半Token，特征原值、原空间位置、来源范围和时间信息同步保留，不新增相似度、问题评分、刷新周期或训练。48/96等偶数节点按一半选择；未覆盖的奇数/非法节点应在预检拒绝，不能临时补规则。

选择它是为了单独检查“存与读分开”是否可行，并建立以后更强读取器必须超过的简单基线。旧M0上odd已有退化，这一点必须保留；它不是预判最佳压缩器。change24依赖相邻真实帧对的对应位置差分，而合并节点未必有这种对应关系，直接将其套到森林节点会引入新的评分定义，因此首轮不这样做。

### 六组，固定三个银行

| 银行，均沿原完整48写入与384保存预算 | 完整读取参照 | 临时半数读取 |
|---|---|---|
| 原M2事件森林 | 最多384视觉Token | 最多192视觉Token |
| A06 | 最多384 | 最多192 |
| LS | 最多384 | 最多192 |

本方不修改搭档正在研究的记忆更新规则。每个银行的两条读取路径必须使用完全相同的节点、时间范围与融合轨迹；问答后银行摘要相同。临时半数读取会改变语言序列长度和位置布局，其影响属于本轮读取路径的一部分，不能声称已把语义损失与位置影响拆开。

M0无融合场景用作CPU等价检查：同八对、相同选择索引时，读取时odd与旧odd24_8应导出相同读取特征/位置；不为它额外开第七、八个GPU臂。

### 数据、评估和推进门槛

- 先用现有全部303时刻做一次开发与回归验证，不抽取只对候选有利的题。分报natural171、T98、长支持16、人工6；含歧义的其余长题只作补充。六组共1818正式回答、最多14544正式生成Token。
- 旧完整M2/A06/LS结果作为回归目标；不是用历史秒数代替新参照。每个银行导出后轮换问答顺序。正式最多3981次共享视觉编码、一次FP32载入；预热与接口微型调用另列并在提交前冻结，暂设含预热总上限1830答、14640生成Token、4005次视觉调用。
- 报告完整读取正确/压缩错误、完整错误/压缩正确，按来源汇总，并保留基础失败。格式合规单列，不并入内容正确率。置信区间如计算，按来源分组，不能把同一视频问题当独立样本。
- 计时主指标是完整问答成本（含临时导出/选择/搬运和语言计算）及首Token时间，银行更新时间和额外内存一起计账。共享视觉实验不能声称独立全流程加速。
- 工程门槛：主银行逐步状态与完整参照完全一致，模型只读截至提问的证据，回答后临时状态释放；失败即停止能力解释。
- 候选进入新来源确认的预设门槛：至少一个银行在主269及长支持16均无净正确数损失，且本轮该银行QA累计耗时至少降低15%。15%是本阶段工程筛选阈值，不是统计显著性或保证无损；所有逐题损失仍须披露。人工6单列，不能用它抵消支持题退化。
- 若多个银行通过，不因分数最高新增排名探索：按事先顺序LS→A06→M2选择一个组合进入新源验证，其余保留回归结果。该顺序基于旧开发信号预设，不能看本轮结果后改变。
- 若没有通过，关闭这一简单“读取时半数选择”首版，不继续改odd偏移、比例、提示词或为旧错误题设例外。不据此否定所有读取压缩，也不自动开新压缩算法。

**拟资源上限：** 同项目g078t/gx_llm、1A800、4CPU、24GiB、45分钟、日志96MiB，不训练、不下载、不自动重试；本次只设计，脚本、预检和GPU许可均未完成。结果拟用独立`experiments/2b-readout-compression-v1`及对应新runs目录，原冻结P3及搭档源码不动。

### 必须保留的比较边界

本轮回答“固定原银行以后，可以压缩多少读取”，不直接证明“晚压一定优于早压”。原P3入库前压缩会改变历史覆盖、融合及读取Token数；若直接拿P3分数与本轮相减，不能把差值全部归因于时机。当前无需为纯时机归因增加另一套复杂的受控融合实验。

本轮保持原银行存储，主要目标是回答更快；没有节省银行存储的主张。原M0实验中银行只有约3MiB，而权重约8GiB，不能用银行压缩比例宣传显著降低整机显存。保存预算与读取预算应成为两个独立配置项。

## 6. 搭档数据交付后的确认

本方不重新组织视频下载和内容标注。需要搭档交付冻结的来源ID、视频与采样规范、查询时刻、问题/答案、证据可见性及审核状态，注明开发/未见属性；我们负责输入接入、运行和比较。

实验二如通过，只把冻结的一个组合带入新来源集，与同银行完整读取参照比较一次；内容阈值、样本量与来源分组须在查看新结果前登记。当前不知道交付规模，不能预先承诺能证明2个百分点等小差异，也不能把旧支持16的无净损失当作已通过非劣效检验。

确认中须同时报告近期感知、旧事件、细节和顺序的结果与退化，并尊重搭档标注的实际记忆需求。未见数据到位前，不把其他已打开的303题换名为测试集。

如果数据暂未到位，完成接口、固定代码和已有回归后明确暂停能力结论，不用反复旧集调参填补等待。确认无可用折中则阶段性报告负结果，不自动启动FastV、KV剪枝、训练或新的缓存方案。
