# T独立新来源验证准备

沿用实验总纲1.47与事前T准入协议。本文件说明复现流程；实际授权、运行与完成状态只读实验总纲，不以准备阶段协议中的历史状态字段判断当前进度。

数据来自已取得的NExT-GQA官方原题、时间区间、VIDOR映射和原ZIP目录。
剔除已有124视频的身份，其中84段来自NExT-GQA；来源ID不同不证明独立拍摄。
确定性选择40段、119原题：20段30—59秒、19段60—119秒、一段180秒。
最后一段只有2题，保留题量缺口。39个三题来源分别覆盖近期、早期短区间及顺序/可见原因代理。
所有代理都需要实际画面审核，不能作为正确标签、可答性或历史必要性的保证。

工作顺序：

1. `prepare.py`：冻结名单、原题、原标签、来源和校验锁，不联网。
2. `acquire.py metadata`：固定镜像版本的小型文件元数据检查。
3. 用户批准后，`acquire.py download`：单次获取、逐文件SHA/大小/作者CRC检查。
4. `review_media.py freeze`、`review_media.py run`：固定1FPS、192×256等比补边，全前缀图页；只缓存24张RGB，检查图页裁切与实际输入逐字节同一。
5. 实际查看全部图页后才写内容审核：保留歧义、后期重复、旧窗口覆盖、同源/同家庭疑点和第二人复核状态。
6. 内容准入冻结、接口/容量预检、具体GPU申请后，才进行原模型及固定记忆候选对照。
7. `freeze_runtime.py`、`transport.py`：冻结运行依赖、部署个人项目并做原生/记忆两阶段CPU预检。
8. 获得本次明确授权后，`control.py submit`只允许一次提交；`observe`仅查询自己的作业，`fetch`有界取回文本证据。
9. `analyze.py`使用冻结评分规则分析全部784条结果；`audit_results.py`补充描述性资源与逐题得失审计，不改主评分。

分析协议在`freeze_analysis.py`固定：原模型与完整成对参照、M0、M1、M2、B02首版、蓄水池、纯文字。
权重、压缩、分组阈值和随机种子固定；不根据本批结果追参数。
最多119×8=952回答，实际准入数量只能在画面审核后确定；这不是已完成的GPU测试。

复用的完整原模型输入函数有3072Token工程上限，180秒1FPS可能超出。
后续必须先用同一完整输入明确核验容量；不截掉历史、不单独降一组采样率、不隐瞒容量失败。
实际运行适配器另见`evaluate.py`，不覆盖旧冻结函数。长期视频层仍不足，119候选题不是覆盖全部长期能力的正式榜单。
