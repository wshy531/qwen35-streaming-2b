# 统一评测入口

2026年11月5日清单快照。日常进度与授权见项目《实验总纲.md》。

| 清单名称 | 内容 | 用途 |
|---|---|---|
| development | StreamingBench 150题、均衡短片60题、配对诊断18题 | 开发与选模，分别报告三个分组 |
| regression | 开发组中的StreamingBench 75题及同一批短片60、诊断18，共153题 | 例行退化检查 |
| short_validation | 60个新项目来源，60题，四档时长各15题 | 方法冻结后的短片验证 |
| streamingbench_candidate | 首批12视频13题 | 媒体技术通过，拍摄来源隔离待确认 |
| diagnosis_anchors | 30视频60道作者原题 | 指定早晚时刻的普通读取核验；不等同历史依赖题 |
| diagnosis_candidate | 11组22题配对草案 | 当前／历史同刻证据复核，暂不作正式验证 |

development 的三部分另有 development_streamingbench、development_short、development_diagnosis 三个视图，它们引用同一组题目。regression 也是 development 的子集。计数时按题ID去重，选项排列不增加独立问题数。

NExT-QA包含人物活动、动作与物体等短视频。均衡短片面板四档为10–20、20–40、40–60、60–90秒。StreamingBench包含真实活动、手工、体育、游戏、科技评测与动画等混合内容。S-EMBER旧配对诊断来自既有五个只读视频，仅用于熟悉案例的归因。

例行工作优先复用这些已有清单。现有200段StreamingBench视频足以继续扩充已打开开发回归的任务覆盖，新来源扩容承担独立验证用途。S-EMBER478保留为阶段性历史细节检查。EPIC、VideoCon的旧动作/证据监督数据归档为训练分支资料，不加入当前统一评测总分。

## 查看和导出

在项目根目录执行以下命令。

```powershell
python experiments/eval-consolidation-20261105/dataset_cli.py inspect --suite short_validation
python experiments/eval-consolidation-20261105/dataset_cli.py export --suite short_validation --out runs/short-validation-inputs.json
```

导出题单包含固定提示、媒体路径和提问时刻，不包含答案。options 统一去除原有字母前缀，再由现有B协议添加一次字母。original_options保留原始文本，答案索引不变。registry.json绑定各题单SHA，改动后会拒绝使用旧注册记录。

评分输入为同一方法的完整JSONL，每行包含id和text。以原选项顺序进行主评测。

```powershell
python experiments/eval-consolidation-20261105/dataset_cli.py score --suite short_validation --answers runs/short-answers.jsonl --out runs/short-scores.json
```

答案键为answer_keys_LOCAL_ONLY.json。评分器按完整题单检查未知题号、重复与缺失，未解析/冲突回答单列。存在未决项时先输出正确数、错误数和未决数，待内容复核再报告正确率。解释是否有依据按另行冻结的辅助判读规则评价。
