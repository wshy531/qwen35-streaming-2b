# V1：Qwen3.5成对视觉计算复用

持续进度只读项目根目录`实验总纲.md`1.92起。CPU证据、冻结清单和GPU提案在`runs/2b_vision_cache_prepare_20261024_01/`。本目录不改变旧实验或默认模型。

## 目标与边界

此前48→24的选择器在完整视觉编码之后删除输出，减少语言模型读取量。本候选在视觉编码器内部复用部分参考结果，保持每对画面输出48Token，试验视觉计算能否减少。二者作用位置不同；本轮先不组合，避免混淆收益来源。

只读参考为已有STC项目`cf53f781d8740df5c07d7924756acc429641ffd0`的`stc/cacher/reference_forward.py`、`stc/core/selectors.py`及`stc/config.py`，另有两资料源中的Token压缩笔记。实际参考缓存K/V/注意力输出/MLP输出；笔记将后两项解释成权重和掩码，不能据此实现。

这是对当前Qwen视觉层的最小适配，不是原版STC全流程复现。未接STC-Pruner、CUDA graph、长期记忆新算法或训练。

## 固定首版

1. 一次输入一个完整帧对。视觉时间patch为2，192个空间patch经24层后合并成48个2048维投影Token。
2. pair0/2/4…完整计算，并在每层保存参考K、V、注意力输出和MLP输出。
3. 其他帧对先计算当前层全部K；首层按当前K与参考K余弦相似度选最不同的25%位置，后层共享选择。
4. 只对所选位置计算Q/V、注意力查询、输出投影和MLP；V的其他位置及静态注意力/MLP输出来自参考。当前残差仍保留。
5. Q/K继续使用当前网格的视觉RoPE。融合QKV权重按行切片使用，没有新建或训练权重。
6. 新来源显式清空缓存；网格/输入dtype/device变化完整刷新；非法输入或异常清空并停止。解绑恢复原forward并释放参考。

仅支持eval、无梯度、SDPA、单时间patch、偶数空间网格。额外视觉输出选项拒绝，支持模型实际桥接需要的`return_dict=True`。`bypass()`让同一进程的原始视觉对照调用原forward，不推进或改写候选参考；没有同时安装两份缓存。

## 内存与证据口径

FP32参考张量为`4 × 24 × 192 × 1024 × 4 = 75,497,472`字节，即72MiB，固定独立于视频长度。还有临时重组张量、模型权重、8对画面银行与临时语言状态，72MiB不代表总内存。

逐问答用步数/指针/适配器写入计数检查参考不变，避免每题搬运72MiB做SHA；这是受控调用路径的修改审计，不是任意外部写入的密码学保证。CPU微型问答另实际逐张量检查了值不变。

`CPU_mechanism_v3.json`是当前缓存源码对应的最终微型机制检查：完整路径、100%更新、重复输入、原路径bypass、实际MLP行数192→48、周期/网格刷新、reset、异常清空、解绑和权重不变等。变化输入的近似特征误差保留，不当作真实模型准确率。

`CPU_preflight.json`覆盖112来源/303问题时刻×两臂的606个完整问答布局，输入ID摘要与旧full48_8参照一致；另有4次随机微型模型问答、8次视觉调用及问答后继续接收与显式尾帧补齐。均无预训练权重载入或GPU。

## 真实对照设计

- 原完整视觉与缓存首版；两边都是M0最近8对、384视觉Token，每对48Token，无持续语言主KV或完整历史特征档案。
- 固定303问题时刻/112来源，含原开发171、T98与六长来源34次中途查询。长视频仍按旧因果协议提问，不等到EOF才统一问。
- 每对画面交替两种编码顺序，每题交替问答顺序。两臂独立视觉编码及银行，文件解码共享；因此仅将视觉分项时间作本轮速度证据，不能当独立方法全链或端侧/1倍速实测。
- 使用V0的auto4解码实现副本，两边输入相同。实际每个采样画面的RGB SHA/PTS仍验证，原冻结GPU脚本不变。
- 预热前用真实权重的100%更新做一次数值验收；失败停止，不自动重投或改阈值。
- 正式606答/7962视觉调用，另2预热答/16视觉调用及4次数值验收视觉调用；合计最多608答、4864生成Token、7982视觉调用、一次FP32载入。
- 内容正确性为主、格式单列；主269和支持长16分别检验，原28/人工6及逐题得失另报。所有集合已用于开发，不声称新留出或泛化收益。
- 候选保留门槛：主269和支持长16均无净正确题损失，视觉时间在全部来源与六长来源汇总中均降低，旧完整视觉参照无漂移。通过也仅保留候选，不证明稳定改善；未通过则本首版收尾，不扫描比例、刷新间隔或新增视觉修补分支。

## 执行文件

`cacher.py`是会话缓存；`banks.py`是两臂相同的最近8对；`solo_session.py`逐字复制已验证的独立问答实现；`session.py`交替调度两臂；`io_source.py`复制V0有界输入；`preflight.py`检查布局及微型问答；`evaluate.py`在已获授权的Slurm任务中运行；`analyze.py`分开分析内容、格式、旧参照回归和视觉成本。

`inputs/execution_lock.json`冻结执行源码和输入SHA。`GPU_authorization.json`尚未创建，执行器需要它与本次冻结SHA相符，且需要集群CPU回执。不能只因为脚本已存在就启动GPU。

提案资源：g078t / gx_llm，1张A800、4核CPU、24GiB系统内存、45分钟，日志上限64MiB；不训练、不下载、不自动重试，提交时须禁用requeue。源项目仅在授权根目录内只读核对。
