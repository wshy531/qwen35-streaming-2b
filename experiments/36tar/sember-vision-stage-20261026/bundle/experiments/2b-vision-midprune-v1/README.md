# 视觉中层固定分组剪枝：一次成本可行性预检

持续进度只看《实验总纲》1.118。本目录固定第一轮假设与比较，不作为另一份进度记录。

## 问题与改动

现有108→54选择发生在视觉编码之后，省不了完整ViT前向。S-EMBER固定成本面板里，QA约占8.71%、视觉约21.04%，所以单靠QA两倍提速的总成本理论收益约4.35%。旧change24也已观察到QA明显省时、完整流程收益小。

本轮只改剪枝位置：

```text
已有后置选择：432 patch → 全部24层 → merger输出108 → 固定选择54
本候选：      432 patch → 前12层 → 保留54个完整2×2组（216 patch）
                              → 后12层 → 原merger输出54
```

每个选中组的4个patch都保留，旋转位置仍用原坐标，不重排为新的密集网格。最终54特征记录其原9×12网格位置。固定odd选择是用于隔离“何时剪枝”的简单控制，不宣称内容选择最优或论文创新。ToMe/DTD/STC本地笔记提供的是内部缩短序列、保留位置和分层成本原则；本实现不是那些论文的完整复现。

该机制不保存上一帧的视觉层缓存，与已关闭的V1缓存首版不同。每个新帧对都重新计算当前保留位置，不调整分辨率、采样率、语言模型混合状态或记忆森林。

## 当前只准备R1：真实视觉成本

固定4个S-EMBER开发来源、每源10%/50%/90%位置的3个真实帧对，共12对；名单按来源SHA排序选择，未读问题、答案或模型成绩。媒体复用本地已有副本，集群只读用户提供的既有开发视频目录，不下载或复制全集。

比较原完整视觉、后置odd54、中层odd54。每对各模式5次预热、20次计时，并轮换运行次序；另各做一次原始和全保留重放数值控制。总924次完整或剪枝视觉前向，1次FP32真实权重载入，0问答/0生成。最多缓存12对RGB约7.59MiB，不保存完整采样视频或视觉历史。

固定门槛：全保留重放数值检查通过；12对的中层/完整时间比中位数≤0.85，慢于完整的帧对最多3对。若失败，则当前首版成本门槛失败、停止，不扫层数或比例。该门槛不能判断回答质量；即使通过，也只激活下一轮正式质量/完整成本准备。

计时包含完整视觉调用和选择的Python/GPU操作，输入已预先准备；不包含解码、processor和问答，不能报告端到端、端侧、实时或准确率收益。真实GPU预算拟g078t/gx_llm、1A800、4CPU、24GiB、15分钟、日志16MiB，无训练/下载/重试/requeue。新的具体GPU批准前不提交。

## R2、R3明确排期

R1通过后，R2用原全部478题、固定最近8对覆盖，对比full108/post-odd54/post-change54/mid-odd54，并在已有12源57题面板独立测完整流程成本。目标为成本至少省5%、总分净损失不超过4题且旧85题不净下降；这只是工程候选门槛，不冒称统计非劣或自动升级默认。已有478题是开发数据，泛化仍需搭档的新来源。

## CPU检查范围

`cpu_preflight.py`使用随机微型模型验证：全保留输出与原视觉路径相同、后置选择一致、真实层内序列减半、完整2×2组和原坐标保留、A→B→A没有跨帧状态、权重不变、54特征能进入独立QA上下文且释放。CPU检查不证明真实权重质量或GPU加速。

`evaluate.py`没有Slurm分配与绑定源码的GPU批准文件就拒绝载入真实权重。`run_cost.sh`使用LF换行；加载/输出记录只写JSON可序列化基本类型，先完整序列化再打开文件。
